# TradeCSV v0.1.0

First release of TradeCSV: a local checker and normalizer for spot trade-fill CSV files.

## What it does

- Reads one UTF-8 CSV of spot fills (one row = one executed trade) and checks every record: time zone present, plain decimal numbers, positive price and quantity, explicit side, valid asset codes, fee currency stated, fee sign convention known.
- Reports problems with a code, record number, field, message and hint. Counts always add up (`total = accepted + rejected`; blank rows separate; unknown when the CSV structure is broken).
- Detects identical copies, conflicting records with the same trade id, and suspected duplicates without an id. Nothing is deleted; conflicts are rejected without picking a winner.
- Exports lossless JSON (all decimals and ids as strings, UTC times), a spreadsheet-friendly CSV with formula protection, and a JSON report. With errors, only the report is written unless partial export is explicitly enabled.
- Works with the project's Spot Fills Template v0.1 or any CSV described by a data-only mapping file.
- Core library with no file system, network or DOM access; thin CLI (`check`, `convert`, `template`).

## Not included

No exchange-specific adapters yet (no official CSV format evidence was found for OKX; see `docs/formats.md`). No derivatives, P&L, tax, API access or network use.
